# Архитектура PWA и фоновая работа на iOS

Документ описывает архитектурные решения Progressive Web App (PWA), интеграцию с Web Bluetooth API и преодоление специфических ограничений выполнения JavaScript в среде **Apple iOS WebKit**.

---

## 1. Специфика платформы iOS и ограничения WebKit

Среда iOS накладывает ряд системных ограничений на работу браузерных диагностических приложений:

1. **Отсутствие Web Bluetooth в Safari:** Apple не включает Web Bluetooth API в стандартный браузер Safari. Для работы с адаптерами ELM327 BLE требуется специализированный браузер со встроенным мостом между WebKit и фреймворком CoreBluetooth (рекомендуется **[Bluefy — Web BLE Browser](https://apps.apple.com/app/bluefy-web-ble-browser/id1492822055)**).
2. **Приостановка выполнения JavaScript при сворачивании:** при переключении пользователя в навигатор, плеер или на экран блокировки WebKit снижает приоритет фоновой вкладки, замедляет либо полностью останавливает таймеры `setTimeout` / `setInterval` и блокирует цикл `requestAnimationFrame`.
3. **Ограничения фонового BLE:** операционная система стремится высвободить радиомодуль и память при длительном нахождении приложения вне фокуса.
4. **Конфликт сетевых интерфейсов Wi-Fi:** диагностические адаптеры с Wi-Fi монополизируют сетевое подключение смартфона, отключая сотовый интернет и лишая водителя онлайн-навигации.

Priora Diag M73 ProLog решает эти проблемы на архитектурном уровне, сочетая Bluetooth Low Energy, PWA-кэширование и подсистему непрерывности сессии.

## 2. Комплекс непрерывности сессии (Background Continuity)

В модуле [`app.js`](../app.js) развернуты три взаимосвязанных механизма:

```text
┌────────────────────────────────────────────────────────┐
│             Жизненный цикл диагностической сессии       │
└──────────────────────────┬─────────────────────────────┘
                           │
         ┌─────────────────┼─────────────────┐
         ▼                 ▼                 ▼
 ┌───────────────┐ ┌───────────────┐ ┌───────────────┐
 │ Ambient Audio │ │ Screen Wake   │ │ Silent BLE    │
 │ Keeper        │ │ Lock          │ │ Reconnect     │
 │ (Фоновый ток  │ │ (Удержание    │ │ (Восстановле- │
 │  JS-таймеров) │ │  подсветки)   │ │  ние сессии)  │
 └───────────────┘ └───────────────┘ └───────────────┘
```

### Фоновый аудио-кипер (Ambient Audio Keeper)

Для сохранения непрерывности циклического опроса K-Line при кратковременном переключении в другие приложения (например, для просмотра маршрута в навигаторе) используется класс `BackgroundKeeper`:

* Через Web Audio API создается аудиобуфер с цикличным воспроизведением неслышимого потока тишины (PCM с нулевой амплитудой).
* Аудиосессия настраивается в режиме `ambient`:
  ```javascript
  if ('audioSession' in navigator) {
    navigator.audioSession.type = 'ambient';
  }
  ```
* **Поведение в системе:** категория `ambient` указывает подсистеме iOS CoreAudio, что звук приложения является фоновым и не требует монопольного захвата аудиоустройства. Это позволяет поддерживать работу JavaScript-потока в фоне, не прерывая воспроизведение музыки (Apple Music, Spotify, Яндекс Музыка) и не заглушая подсказки навигатора.
* **Технические границы:** аудио-кипер эффективно защищает сессию при повседневном переключении между приложениями. Однако при экстремальном дефиците оперативной памяти (Memory Pressure) или длительном глубоком сне устройства iOS может принудительно выгрузить фоновую вкладку.

### Удержание экрана (Screen Wake Lock API)

Класс `WakeLockManager` при активной связи с ЭБУ запрашивает системную блокировку перехода экрана в спящий режим:
```javascript
this.wakeLock = await navigator.wakeLock.request('screen');
```
Экран смартфона в автомобильном держателе остается включенным на протяжении всей поездки, обеспечивая постоянный визуальный контроль температуры охлаждающей жидкости, напряжения бортсети и детонации. При отключении от адаптера блокировка экрана немедленно снимается.

### Бесшовный авто-реконнект (Silent BLE Reconnect)

Если соединение Bluetooth кратковременно прерывается из-за помех или переходов операционной системы:
* Драйвер [`elm327.js`](../elm327.js) сохраняет дескриптор `BluetoothDevice` в оперативной памяти.
* Обработчики событий `visibilitychange` и `focus` инициируют автоматическое восстановление соединения `await device.gatt.connect()` при возвращении в приложение.
* Подключение выполняется в фоновом режиме без повторного вызова системного диалога сопряжения.
* Сессия записи лога в [`logger.js`](../logger.js) не обнуляется — входящие кадры продолжают записываться в текущий временной ряд.

## 3. Автономный режим и локальное хранилище

Приложение спроектировано по архитектурному стандарту **Offline First**:

```text
[Пользователь] ──► [Service Worker] ──► [Cache Storage] (v55.1)
                          │
                   (Нет интернета)
                          │
                          ▼
             [Автономный запуск PWA]
                          │
                          ▼
             [Локальная база IndexedDB]
                          │
                          ▼
             [Локальный экспорт XLSX / CSV]
```

### Кэширование через Service Worker (`sw.js`)

* **Первый запуск:** при наличии интернет-подключения браузер загружает ресурсы приложения и регистрирует Service Worker с версией кэша `m73-diag-cache-v55.1`.
* **Последующая работа:** все критические файлы (`index.html`, `styles.css`, `.js`-модули, манифест, иконки и локальная библиотека `xlsx.full.min.js`) отдаются напрямую из локального хранилища браузера по стратегии Cache-First.
* Приложение полностью работоспособно в подземных паркингах, гаражных кооперативах и на загородных трассах в условиях полного отсутствия сотовой сети.

### Локальное хранилище поездок (`TripStorage`)

* Класс `TripStorage` в [`logger.js`](../logger.js) использует браузерную базу данных **IndexedDB** (база `Priora_M73_Logs`, хранилище `trips`).
* При отключении зажигания или завершении поездки массив телеметрии автоматически сериализуется и сохраняется на накопителе устройства.
* Метод `_pruneOldTrips(10)` автоматически ротирует журнал, сохраняя 10 последних поездок с их метаданными (дата, время, количество точек, максимальные зафиксированные обороты).
* Генерация файлов `.xlsx` производится локально встроенной библиотекой SheetJS, исключая отправку телеметрии на удаленные серверы.

## 4. Модульный интерфейс виджетов и графический движок

Модуль [`dashboard-widgets.js`](../dashboard-widgets.js) обеспечивает настраиваемую компоновку приборной панели:

* **Режим редактирования (Jiggle Mode):** активируется кнопкой редактирования в шапке панели. Позволяет масштабировать карточки (одиночный размер или растягивание на две колонки), удалять неактуальные датчики и добавлять параметры из встроенной библиотеки.
* **Сенсорный Drag & Drop:** оптимизированная обработка сенсорных координат (`touchstart`, `touchmove`, `touchend`) с расчетом перестановок элементов сетки и аппаратным ускорением CSS Transforms.
* **Осциллограф на Canvas:** вывод графиков датчиков (ДК1, ДК2, ДМРВ, Обороты, Дроссель, УОЗ, Впрыск, Детонация) через `requestAnimationFrame` с автоматическим масштабированием амплитуды (Auto-Scale) и референсной линией стехиометрической смеси 0.45 В.
* **Персистентность конфигурации:** пользовательская раскладка виджетов сохраняется в `localStorage` и восстанавливается при каждом запуске.
