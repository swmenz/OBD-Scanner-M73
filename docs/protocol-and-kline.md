# Протокол KWP2000 и арбитраж шины K-Line

Документ описывает программно-аппаратную реализацию взаимодействия с электронным блоком управления **Итэлма М73** (микроконтроллер ST10F273) по протоколу **KWP2000 (ISO 14230-4)** через диагностический адаптер **ELM327 BLE**.

---

## 1. Физический уровень и инициализация канала

Шина K-Line представляет собой однопроводную двунаправленную линию связи с открытым коллектором (логический 0: $0\dots1.5$ В, логическая 1: напряжение бортовой сети $12\dots14.4$ В). Обмен осуществляется на фиксированной скорости **10400 бод** с форматом кадра 8-N-1 (1 стартовый бит, 8 бит данных, без контроля четности, 1 стоповый бит).

При скорости 10400 бод передача одного байта занимает $\approx 0.96$ мс. Полный кадр телеметрии `21 01` (74 байта полезных данных вместе с префиксом ответа `61 01`) требует около $75\dots85$ мс на физическую трансляцию по шине. С учетом задержек межбайтовых интервалов контроллера ST10F273, буферизации UART адаптера ELM327 и латентности BLE-пакетов реальный темп циклического опроса составляет **3.5–4.2 Гц**.

### Последовательность Fast Init

Инициализация сессии выполняется по стандарту ISO 14230-4:

1. На линию выдается низкий уровень длительностью $T_{\text{iniL}} = 25 \pm 1$ мс.
2. Линия возвращается в высокий уровень на $T_{\text{iniH}} = 25 \pm 1$ мс.
3. Адаптер передает запрос старта сессии: `81 10 F1 81 FC` (Target: `0x10` — ЭБУ, Source: `0xF1` — сканер, Service: `0x81` — StartCommunication, Checksum: `0xFC`).
4. Контроллер М73 отвечает позитивным подтверждением `C1 EA 8F` с ключевыми байтами протокола (Key Bytes: `0xEA 0x8F`).

### Инициализационная цепочка ELM327 в `m73.js`

При открытии соединения модуль [`m73.js`](../m73.js) настраивает микроконтроллер адаптера (PIC18F25K80) в скоростной прозрачный режим:

```text
AT Z           ; Аппаратный сброс микроконтроллера ELM327
AT E0          ; Отключение эхо-повтора команд
AT L0          ; Отключение передачи символов перевода строки
AT AL          ; Разрешение длинных кадров (> 7 байт, для 74-байтного кадра 21 01)
AT AT 2        ; Агрессивный адаптивный тайминг (Adaptive Timing Level 2)
AT S0          ; Отключение разделительных пробелов между байтами
AT ST 10       ; Чистый турбо-таймаут ожидания шины ~64 мс
AT SH 81 10 F1 ; Заголовок: Target = 0x10 (ЭБУ), Source = 0xF1 (тестер), Format = 0x81
AT IIA 10      ; Адрес ЭБУ для процедуры Fast Init (0x10)
AT SP 5        ; Протокол 5: ISO 14230-4 KWP (Fast Init, 10.4 kbaud)
AT SW 00       ; Отключение авто-Wakeup ELM327 (управление сессией выполняется явно)
AT FI          ; Запуск физической инициализации Fast Init
AT H0          ; Отключение заголовков (после подтверждения сессии для чистого payload)
```

Отключение заголовков (`AT H0`) выполняется строго после успешного подтверждения сессии `AT FI`, что позволяет сначала верифицировать байты ответа (`C1`, `8110F1`), а затем получать чистый полезный поток данных без избыточных байтов заголовка.

## 2. Арбитраж шины и монопольный мьютекс

Шина K-Line строго полудуплексна: одновременная отправка команды сканером во время передачи ответа контроллером физически разрушает оба пакета на линии. Для исключения коллизий в [`app.js`](../app.js) развернут многоуровневый арбитраж:

```text
[Пользователь / Интерфейс]
        │
        ▼
   isActuatorBusy? ───(Да)───► Отклонить операцию ("Идёт тест механизма, подождите")
        │ (Нет)
        ▼
   isActuatorBusy = true
   _cancelRegulatorRequested = false
   prevPolling = isPolling || shouldBeConnected
   await stopPolling()
        │
        ▼
   [Исполнение сервисной процедуры: DTC / Уставка / Тест / Сброс]
        │
        ▼
   finally: await _finishBusy(prevPolling)
        │
        ├─► Отправка отложенных возвратов: 30 <ID> 00 (_pendingReleases)
        ├─► isActuatorBusy = false
        └─► Восстановление циклического опроса: startContinuousPolling()
```

### Монопольный опрос по экранам

* **Экран «Панель»:** непрерывно опрашивается только базовый кадр `21 01` (ответ `61 01`, 74 байта).
* **Экран «АЦП»:** циклический опрос `21 01` останавливается; опрашивается исключительно кадр кодов АЦП `21 03` (ответ `61 03`).
* **Экран «Ошибки»:** фоновый опрос остановлен. Чтение (`18 00 FF 00`) и очистка (`14 FF 00`) кодов выполняются изолированно.
* **Экран «Тесты»:** фоновый опрос остановлен; выполняются дискретные тесты службы `0x30` либо удерживается активный регулятор уставки.

## 3. Управление регуляторами и очередь отложенных возвратов

Служба `0x30` (Input/Output Control by Common ID) контроллера М73 позволяет временно перехватывать управление исполнительными механизмами:

### Идентификаторы регуляторов уставки

| Параметр | Common ID (hex) | Масштабирование raw | Диапазон регулирования |
| :--- | :--- | :--- | :--- |
| **Положение шагового двигателя РХХ** | `0x41` | $\text{steps}$ | $10\dots200$ шагов |
| **Желаемые обороты холостого хода** | `0x42` | $\frac{\text{RPM}}{10}$ | $600\dots1800$ об/мин |
| **Степень продувки адсорбера (КПА)** | `0x43` | $\%$ | $0\dots100\%$ |

### Формат команд службы 0x30

* **Фиксация уставки:** `30 <ID> 07 <RawByte>` (Control State = `0x07` — временная фиксация параметра).
* **Возврат управления контроллеру:** `30 <ID> 00` (Control State = `0x00` — Return Control to ECU).

### Очередь отложенного возврата управления (`_pendingReleases`)

При удержании уставки контроллер М73 ожидает периодического подтверждения. Если пользователь корректирует значение кнопками `+` / `−`, запускается процедура `applyRegulator(key, true)`.

В момент асинхронной передачи команды по шине K-Line пользователь может нажать «Штатно (ЭБУ)» или переключиться на другую вкладку. При занятом канале команда возврата не может быть передана немедленно.

Для исключения зависания уставки в контроллере реализован механизм отложенного возврата:
1. Метод `releaseRegulator()` при обнаружении занятости канала (`isActuatorBusy == true`) сохраняет идентификатор механизма в очереди `this._pendingReleases.add(idHex)` и взводит флаг отмены `_cancelRegulatorRequested = true`.
2. Завершающий деструктор `_finishBusy()` вызывается в блоке `finally` всех операций, владеющих шиной:
   ```javascript
   async _finishBusy(prevPolling) {
     try {
       const ids = [...this._pendingReleases];
       this._pendingReleases.clear();
       if (this.elm.isConnected) {
         for (const id of ids) {
           try { await this.m73.releaseActuatorControl(id); } catch (e) {}
         }
       }
     } finally {
       this.isActuatorBusy = false;
       if (prevPolling && this.elm.isConnected) {
         this.startContinuousPolling();
       }
     }
   }
   ```
3. При сохранении активного BLE-соединения контроллер получает команду `30 <ID> 00` при первой разблокировке мьютекса, сбрасывает режим переопределения и возвращается к штатным калибровкам. При разрыве соединения или аппаратной ошибке шины деструктор завершается безопасно, исключая блокировку интерфейса.

## 4. Поддержание сессии (Tester Present)

При отсутствии диагностических запросов в течение интервала ожидания ($T_{\text{idle}} \approx 2000\dots5000$ мс) контроллер М73 в целях безопасности закрывает диагностическую сессию KWP2000 и возвращается к стандартному режиму управления двигателем.

Для удержания соединения при нахождении на экранах без непрерывного опроса («Ошибки», «Терминал», состояние покоя в «Тестах») таймер фонового опроса каждые 2000 мс передает короткий запрос службы `0x3E`:
```text
Запрос:  3E
Ответ:   7E
```
Этот однобайтовый пакет удерживает диагностическую сессию открытой без создания паразитной нагрузки на шину.

## 5. Программные защитные блокировки

Для предотвращения аварийных ситуаций клиентское приложение программно верифицирует состояние двигателя по последнему принятому кадру `21 01` перед отправкой управляющих команд:

* **Регуляторы уставки (РХХ, ХХ, Продувка):** разрешены строго при неподвижном автомобиле ($\text{Speed} == 0$). При начале движения ($\text{Speed} > 0$) вмешательство в регулирование автоматически снимается с возвратом управления ЭБУ (`30 <ID> 00`).
* **Дискретные тесты:** тесты вентиляторов 1 и 2 скорости (`0x0A`, `0x0D`) и лампы Check Engine (`0x0C`) разрешены на стоянке ($\text{Speed} == 0$) как на заглушенном, так и на заведённом двигателе; тесты бензонасоса, форсунок, катушек зажигания, кондиционера и стартера разрешены строго на стоянке при заглушенном двигателе ($\text{Speed} == 0$ и $\text{RPM} == 0$).
* **Сброс с инициализацией (перезапуск контроллера):** разрешен строго при $\text{Speed} == 0$ и $\text{RPM} == 0$. После сброса контроллер М73 перезагружается и закрывает сессию связи. Приложение корректно завершает сессию и информирует водителя о необходимости выдержать 10-секундную паузу зажигания для фиксации EEPROM.
