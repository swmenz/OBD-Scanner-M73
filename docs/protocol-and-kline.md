# Протокол KWP2000 и арбитраж шины K-Line

Документ описывает реализацию низкоуровневого взаимодействия с электронным блоком управления **Итэлма М73** (микроконтроллер ST10F273) по протоколу **KWP2000 (ISO 14230-4)** через диагностический адаптер **ELM327 BLE**.

---

## 1. Физический уровень и инициализация канала

Шина K-Line представляет собой однопроводную двунаправленную линию связи с открытым коллектором (уровни: логический 0 — $0\dots1.5$ В, логическая 1 — напряжение бортовой сети $12\dots14.4$ В). Обмен осуществляется на фиксированной скорости **10400 бод** с форматом байта 8-N-1 (1 стартовый бит, 8 бит данных, без контроля четности, 1 стоповый бит).

### Последовательность Fast Init

Инициализация связи выполняется процедурой быстрого старта (Fast Initialization) по стандарту ISO 14230-4:

1. На линию выдается низкий уровень длительностью $T_{\text{iniL}} = 25 \pm 1$ мс.
2. Линия возвращается в высокий уровень на $T_{\text{iniH}} = 25 \pm 1$ мс.
3. Адаптер передает запрос старта диагностической сессии: `81 10 F1 81 FC` (Format: `0x81`, Target: `0x10` — ЭБУ, Source: `0xF1` — сканер, Service: `0x81` — StartCommunication, Checksum: `0xFC`).
4. Контроллер М73 отвечает позитивным подтверждением `C1 EA 8F` с ключевыми байтами протокола (Key Bytes: `0xEA 0x8F`).

### Конфигурация драйвера ELM327

При установлении Bluetooth-соединения драйвер [`elm327.js`](../elm327.js) выполняет инициализационную цепочку AT-команд, переводящую микроконтроллер адаптера (PIC18F25K80) в скоростной прозрачный режим:

```text
ATZ          ; Аппаратный сброс адаптера ELM327
ATE0         ; Отключение эхо-повтора передаваемых команд
ATL0         ; Отключение генерации символов перевода строки (\n)
ATH0         ; Удаление заголовков шины (Header bytes) из возвращаемого ответа
ATS0         ; Удаление разделительных пробелов между байтами
ATSP5        ; Принудительный выбор протокола 5: ISO 14230-4 KWP (Fast Init, 10.4 kbaud)
ATAL         ; Разрешение длинных пакетов (Long frames > 7 байт)
ATIB10       ; Установка скорости инициализации шины K-Line: 10400 бод
ATSH8110F1   ; Задание заголовка сообщений: Target = 0x10 (ЭБУ), Source = 0xF1 (тестер)
ATSW00       ; Нулевой межбайтовый интервал при передаче (минимальная задержка)
ATAT2        ; Агрессивный адаптивный тайминг шины (Adaptive Timing Level 2)
ATST20       ; Аппаратный таймаут шины ~128 мс (быстрый сброс при потере байта)
```

За счет связки `ATAT2` и `ATST20` адаптер не тратит фиксированные 400 мс на ожидание завершения приема, а замыкает цикл сразу после фиксации паузы P2/P3 на линии, обеспечивая темп опроса **3.2–4.8 Гц** для 74-байтного кадра `21 01`.

## 2. Арбитраж шины и монопольный мьютекс

Шина K-Line полудуплексна: одновременная передача запроса сканером во время трансляции ответа контроллером физически разрушает оба пакета на линии. Для исключения коллизий в архитектуре приложения развернут трехуровневый арбитраж:

```
[Пользователь / UI]
        │
        ▼
   isActuatorBusy? ───(Да)───► Отклонить вызов ("Идёт тест механизма, подождите")
        │ (Нет)
        ▼
   isActuatorBusy = true
   _cancelRegulatorRequested = false
   prevPolling = isPolling || shouldBeConnected
   await stopPolling()
        │
        ▼
   [Выполнение сервисной команды: DTC / Уставка / Тест / Сброс]
        │
        ▼
   finally: await _finishBusy(prevPolling)
        │
        ├─► Отправка всех отложенных возвратов: 30 <ID> 00 (_pendingReleases)
        ├─► isActuatorBusy = false
        └─► Восстановление фонового опроса: startContinuousPolling()
```

### Принцип монопольного опроса по вкладкам

* **Вкладка «Панель»:** опрашивается только диагностический кадр `21 01` (ответ `61 01`, 74 байта).
* **Вкладка «АЦП»:** циклический опрос кадра `21 01` отключается; опрашивается исключительно кадр сырых кодов АЦП `21 03` (ответ `61 03`).
* **Вкладка «Ошибки»:** фоновый опрос полностью остановлен. Запросы чтения (`18 00 FF 00`) и сброса (`14 FF 00`) выполняются изолированно.
* **Вкладка «Тесты»:** фоновый опрос остановлен; выполняются единичные тесты службы `0x30` либо удерживается один выбранный регулятор уставки.

## 3. Управление регуляторами и отложенные возвраты

Служба `0x30` (Input/Output Control by Common ID) контроллера М73 переводит исполнительный механизм под внешнее управление тестера.

### Идентификаторы регуляторов уставки

| Параметр | Common ID (hex) | Масштабирование raw | Диапазон |
| :--- | :--- | :--- | :--- |
| **РХХ (положение шагового двигателя)** | `0x41` | $\text{steps}$ | $10\dots200$ шагов |
| **Желаемые обороты холостого хода** | `0x42` | $\frac{\text{RPM}}{10}$ | $600\dots1800$ об/мин |
| **Клапан продувки адсорбера (КПА)** | `0x43` | $\%$ | $0\dots100\%$ |

### Формат команд службы 0x30

* **Установка и удержание значения:** `30 <ID> 07 <RawByte>` (Control State = `0x07` — временная фиксация параметра).
* **Возврат управления контроллеру ЭБУ:** `30 <ID> 00` (Control State = `0x00` — Return Control to ECU).

### Защита от потери команды возврата (`_pendingReleases`)

При удержании уставки ЭБУ ожидает периодического подтверждения службы `0x30`. Если пользователь изменяет значение уставки кнопками `+` / `−`, запускается процедура `applyRegulator(key, true)`. 

В момент выполнения асинхронного вывода в K-Line пользователь может нажать «Штатно (ЭБУ)» или перейти на другую вкладку. Без очереди отложенных команд статус в интерфейсе вернулся бы в состояние «Штатно», но физическая команда `30 <ID> 00` была бы пропущена из-за занятости канала.

В архитектуре v52.1 реализовано гарантированное освобождение:
1. `releaseRegulator()` при обнаружении флага `isActuatorBusy == true` помещает `idHex` в коллекцию `this._pendingReleases.add(idHex)` и взводит флаг `_cancelRegulatorRequested = true`.
2. Завершающий деструктор `_finishBusy()` вызывается в блоке `finally` всех операций, владеющих шиной:
   ```javascript
   async _finishBusy(prevPolling) {
     try {
       const ids = [...this._pendingReleases];
       this._pendingReleases.clear();
       if (this.elm.isConnected) {
         for (const id of ids) {
           try { await this.m73.releaseActuatorControl(id); } catch (e) {}
         }
       }
     } finally {
       this.isActuatorBusy = false;
       if (prevPolling && this.elm.isConnected) {
         this.startContinuousPolling();
       }
     }
   }
   ```
3. Контроллер М73 гарантированно получает сигнал `30 <ID> 00`, сбрасывает режим ручной фиксации и возобновляет штатное регулирование.

## 4. Поддержание сессии (Tester Present)

При отсутствии активности тестера в течение таймаута покоя (обычно $T_{\text{idle}} \approx 2000\dots5000$ мс) контроллер М73 закрывает диагностическую сессию KWP2000 и переходит в штатный режим работы.

Для удержания соединения на вкладках покоя («Ошибки», «Терминал», покой в «Тестах») фоновый планировщик каждые 2000 мс передает стандартный запрос службы `0x3E`:
```text
Запрос:  3E
Ответ:   7E
```
Этот пакет имеет минимальный размер (1 байт) и подтверждает активность диагностического оборудования без считывания тяжелых массивов данных.

## 5. Аппаратные барьеры безопасности

Перед выполнением любых потенциально опасных процедур программа опрашивает актуальный кадр `21 01` и программно проверяет состояние двигателя:

* **Управление уставками (РХХ, ХХ, Продувка):** разрешено строго при $\text{Speed} == 0$ (автомобиль на стоянке). При обнаружении движения ($\text{Speed} > 0$) изменение уставок немедленно блокируется.
* **Дискретные тесты (вентиляторы, бензонасос, форсунки, катушки зажигания):** разрешены строго при $\text{Speed} == 0$ и $\text{RPM} == 0$ (стоянка, заглушенный двигатель, включенное зажигание).
* **Сброс с инициализацией (перезапуск ЭБУ):** разрешен строго при $\text{Speed} == 0$ и $\text{RPM} == 0$. Контроллер М73 закрывает сессию после сброса, приложение корректно отключает BLE-соединение и выводит инструкцию пользователю (выключить зажигание на 10 секунд).
